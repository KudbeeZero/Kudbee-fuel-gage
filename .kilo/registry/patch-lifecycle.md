# Patch Lifecycle Registry (EOE-1 Workstream C)
## Every code change follows: Evidence → Plan → Patch → Verification → Review → Governance → Ready

### Lifecycle States

| Stage       | Description                                      | Required Checks                                   |
|-------------|--------------------------------------------------|---------------------------------------------------|
| EVIDENCE    | Repository and graph evidence locked             | DTHINK query, graph snapshot, SHA captured         |
| PLAN        | Execution plan generated by ISE                  | Task classified, model(s) selected, phases defined |
| PATCH       | Code change produced by Implementer              | Diff captured, files tracked                       |
| VERIFY      | Automated checks run                             | Typecheck, lint, tests, build                      |
| REVIEW      | Architecture and style reviewed                  | Reviewer agent checks, boundary certification      |
| GOVERNANCE  | Constitutional compliance checked                | EDR created, gates evaluated, Article VI enforced  |
| MERGE_READY | All gates passed, promotion eligible             | Certificate issued, lessons captured               |

### State Transitions

```
EVIDENCE ──→ PLAN ──→ PATCH ──→ VERIFY ──┬──→ REVIEW ──→ GOVERNANCE ──→ MERGE_READY
                   ↑                      │
                   └── retry ─────────────┘  (if VERIFY fails)
```

### Immutable Rules
1. No patch enters VERIFY without locked evidence.
2. No patch enters GOVERNANCE without VERIFY passing.
3. No patch enters MERGE_READY without an EDR.
4. Failed verification returns to PATCH (not PLAN).
5. Governance rejection returns the decision record with reasoning.
